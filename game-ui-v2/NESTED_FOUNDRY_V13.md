# Continuous Institution Foundry V13

The existing English cyberpunk Foundry has a new mode at
`native-objective-redesign.html?campaign=v13`. It is not a separate dashboard.
The default V12 view, actual payload, export receipt and historical screenshots
remain available; V13 reuses the same original pixel city, circuit, source,
protocol, process, native receipt and objective-path components.

## Same optimization loop, inspected end to end

1. External own-history designer generates G0 code, protocols, mechanisms and
   wiring. Two actual original-world draws provide declared native losses.
2. The declared conditional sampling policy receives one likelihood-ratio /
   leave-one-out expected-loss update. Its exact before/after logits, latent
   means, gradient, losses and compatibility record remain inspectable.
3. One new native forward uses that G0 vocabulary and updated weights. This
   singleton is forward-only: it cannot create another gradient update.
4. The external designer receives its own three observations and may freely
   redesign G1. Its one native forward also performs no parameter update.

The two own loss scales are `−A` and `−Q + 0.5R`; they are not plotted on a
shared numerical scale. A, Q and R are actual native accepted decisions, sum of
original raw peer-score means on accepted decisions, and review records. Other
objective scores are same-checkpoint development cross-scores, not held-out
observations. There is no implicit quality/fairness/novelty veto. A first scored
world is not silently renamed a historical baseline.

An actual draw with a technical failure remains a null endpoint. A generation
failure has one explicitly labelled sentinel with no native observation ID;
it is not fabricated into two executed worlds. All stage records, requested
counts, error reasons and actual draw arrays are preserved verbatim for budget
interpretation. No successful-invention, superiority, scientific-value,
whole-world pathwise derivative or authenticated autonomous-author claim is
inferred from an executable loop.

The receipt-step control reads audited complete-plan and original-review-routing events in recorded
year/sequence order, including their exact event IDs/hashes and attribution
proofs. It focuses the corresponding actual circuit node. This is an inspection
of the available receipts, not a complete replay of the whole world, an
interpolated temporal simulation, a causal effect estimate, or a fabricated
researcher animation. The pixel city remains explicitly schematic art.

## Evidence contract and export

The independently audited terminal file is the only actual input:

- Audit: `scienceutopia.native-nested-search-independent-audit.v13`.
- Actual classification: `actual-native-qwen-nested-search-development-v13`.
- View: `scienceutopia.nested-foundry-observatory.v13`.
- Receipt: `scienceutopia.nested-foundry-ui-export.v13`.

```sh
node scripts/export-nested-foundry-v13.mjs \
  --audit=/absolute/path/to/independent-audit.json \
  --expected-source=EXACT_40_CHARACTER_FROZEN_SOURCE \
  --expected-audit-sha256=EXACT_64_CHARACTER_FILE_HASH
```

The exporter checks both full canonical LossSpecs, literal graph endpoints,
exact generated/delegated source body hashes, native metric cross-scores,
all three stage identities, unchanged G0 vocabulary in the updated forward,
the G0 updated-weight binding and singleton no-update records. It refuses raw
evidence directories and source-audit overwrites. The browser independently
checks payload bytes, source binding, exact integer pointers and actual/fixture
classification. Neither the exporter nor the browser invokes a model, Docker
or the simulator. There is no arbitrary URL input or inference POST.

Unsafe integer lexical tokens use the same lossless decimal-string and JSON
pointer contract as V12. Tokens are never rounded through JavaScript Number;
source text, existing strings and floating-point lexical tokens are preserved.

## Editable local branch, then the existing workbench

The selected actual observation can be copied into a full JSON draft. Local
structural checks reuse `nativeDesignGraph.ts` and do not restrict an invented
institution to the editor's old family menu. The old visual editor also keeps
declared custom families, nodes, ports, wiring, latency and schedules intact.
The authoritative runtime/compiler validation is still separate.

After a local check, download the exact branch JSON or explicitly open the
existing `native.html` workbench. A source/hash-bound browser-session handoff
imports the **same edited SystemSpec, original observed parent and exact
selected LossSpec**. Editing invalidates the prepared export/link. Async import
does not overwrite intervening edits. The workbench requires runtime validation,
an explicit mission and renewed compute consent before its existing job API
can dispatch anything. No consent, job, observed outcome, live-society binding
or adoption receipt is fabricated. This handoff prepares a **fresh branch**,
not adoption into the old society. Explicit same-society adoption still belongs
to the separately supported consent/session API, not to this static audit.

The branch is labelled `local-unexecuted-draft`, `no_execution: true`,
`no_adoption: true`. It does not mutate the exported audit or raw evidence.
Synthetic fixtures cannot seed the real workbench. If an actual SystemSpec
itself contains unsafe integer tokens, browser branch preparation fails closed:
a lossless server-side import is required instead of changing its semantics to
rounded numbers or decimal strings. Receipt/seed identity fields remain fully
inspectable even in that case.

## Verification

```sh
npm test
npm run typecheck
npm run build
node scripts/verify-nested-foundry-browser.mjs --mode=actual
```

The harness checks all stations and loss rows, stage/policy/receipt inspectors,
local copy/check/export, invalidation and exact existing-workbench import,
desktop/mobile screenshots, no horizontal overflow, no exceptions, no failed
HTTP responses and no non-GET/external requests. It stops its own loopback Vite
and isolated Chrome. The actual browser receipt records the source/export
hashes and handoff scope; no actual execution or adoption is performed.

Before the final independent audit is available, only temporary, prominently
watermarked synthetic browser checks are allowed:

```sh
node scripts/verify-nested-foundry-browser.mjs --mode=fixture
node scripts/verify-nested-foundry-browser.mjs --mode=fixture --scenario=zero-replies
node scripts/verify-nested-foundry-browser.mjs --mode=unavailable --output=/tmp/v13-unavailable-qa
```

There is no public fixture payload. Synthetic exports and captures must remain
under the system temporary directory and must not be published as actual results.
