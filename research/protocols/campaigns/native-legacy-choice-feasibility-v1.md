# Original native choice-route feasibility: prospective small control pilot

Prepared November15 while the frozen longitudinal unused evaluation continues.
This does not change that experiment or dispatch a new world. All earlier
development outcomes and two partial unused control outcomes are already
known; this is not a blind pre-result hypothesis or a new held-out test.

## Question and scope

Does removing the inherited core-only direct assignment expose the original
legacy core+related researcher choice, and can a code-defined information
institution influence that choice without changing the original catalog,
researcher weights, durations, corpus, submission rules or resource laws?
The earlier20/36 schedule arithmetic is not a feasible-policy result or bound.
This is developer-authored feasibility/control work, not automatic invention,
an optimizer comparison, a new loss or a conference contribution by itself.

## Three literal institution conditions

Use the same declared post-funding-cost institution as the common anchor.
Only the following differences are permitted by this particular comparison;
they are not restrictions on future free institution design.

1. `core-assignment`: retain the literal inherited catalog assignment policy.
2. `native-choice`: change that producer's existing actuation from `project`
   to `cut`, so it emits no assignment/context command. Original research
   direction selection is free to execute. Do not invent a new assignment API.
3. `native-choice-advice`: retain condition2 and add a sandboxed information
   office plus the existing native context receiver, wired before research.
   It computes the original core+related catalog union for actual idle active
   authors and recommends minimum original duration, with lexical tie breaking.
   Its message includes original topic/duration data and explicit effective year.
   Native scientists may comply or not; no host implements the advice as action.

`utopia.system.native_legacy_choice_controls.controls` constructs these
literal systems without execution, model calls, outcome inspection or selection.
The advice source is ordinary code.python.v1 under the existing networkless
executor. Its only output is addressed context; it cannot directly mint papers,
change project calendars, allocate resources or change measured quality.

sets and durations, delivered advice, actual project/calendar applications,
