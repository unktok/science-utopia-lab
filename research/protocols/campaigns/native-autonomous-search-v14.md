## Question and unchanged world

Can an explicit loss and finite budget drive automatic LLM institution authoring,
technical validation, isolated source execution, original-world evaluation and
own-history redesign without manually answering a ManifestInbox request?
The design object includes arbitrary source, parameters, mechanism composition,
protocols, wiring, schedules and processes. Existing APIs are reused, not a new
closed catalogue of scientific institutions. Retention and failed invention are
legal outcomes. A native system is not replaced by a simpler numeric world.

Five original researchers, two simulation years, development seed42, four-year
real103107-document corpus, fixed researcher Qwen3:8B weights and768-token
researcher response cap are unchanged from v13. Start from the exact existing
`open_native_system` seed example; its pre-existing authored code is disclosed
as developer seed code, not claimed as newly invented by the designer. New
source bodies and graph changes are reported literally, including no-ops.

## Losses and fixed run schedule

Use unchanged exact LossSpecs `native-joint-v5-throughput` (`-A`) and
`native-reviewed-production-efficiency-v13` (`-Q+0.5R`). Q remains the sum of
original integer-parsed reviewer means on accepted decisions; unreviewed
acceptances contribute zero. R counts real review records. No merit, fairness,
minimum-review, novelty or promotion veto is introduced. Validity, held-out
metrics and optional adoption remain separate. Cross-scores reuse development
checkpoints, not unused seeds.

updated G0 remains charged, not replaced. Native failures remain null, never a
fabricated penalty. All ties and worse outcomes are preserved.

## Automatic author and technical attempt budget

The institution designer is **local fixed Qwen3:8B**, separately attributed from
the researcher role. Its tag digest must equal the operator-pinned digest.
No external Codex specialist supplies any actual pilot candidate. It receives
the exact current parent, full LossSpec and deterministic own-history view of
every scalar outcome/failure and saved update. Repeated old full candidate
bodies are represented by hashes in that prompt view; the complete original
request/history remains archived. This is disclosed projection, not a claim
that every historical byte appears in the model context. No future/other-arm
outcomes enter a request.

Each free generation has at most **2 attempts**, each at most4096 output tokens,
temperature0.2, thinking off, fixed per-request seed and explicit32768 context
setting. The prompt has an explicit240000-byte cap; over-budget prompts fail
without silently dropping history. Maximum **12 generation HTTP POSTs**; digest
verification GETs are separate, at most one per attempted generation dispatch.
Completed response/elapsed/token receipts distinguish intentions, actual POST
payloads and known raw HTTP responses. No network/SDK retry or claim of
exactly-once HTTP dispatch. A crash between durable dispatch intent and completed
receipt consumes that attempt with unknown response, never redispatches it.

Model output is an arbitrary atomic JSON-pointer add/remove/replace transaction,
conditional factors/coordinates and rationale. Compilation adds only the known
parent/image/provenance envelope, never repairs source or invents missing
wires/scores. Technical errors may be fed to the next bounded model attempt.
Successful validation is structural/AST/distribution validation, not a hidden
scientific-value gate or a native test with uncharged scientist calls. Generated
Python is data and runs only through the existing pinned networkless Docker
executor. Exhaustion produces an invalid-vocabulary failure record, not an
identity fallback. Explicit model-authored identity remains legal.

## Execution, UI and accounting

The actual pilot calls the same `NativeSearchController` used by the authenticated
local queue. This CLI is operator-authorized; raw paths and host modules are not
UI-selected. UI queue/consent/cold-restart verification uses explicitly SCRIPTED
requests unless an actual execution is explicitly bound to this eight-slot plan;
no extra UI native trial is granted. The local operator binds source, model,
corpus/dataset and container image. Native checkpoint bindings retain Python
hash environment/probe. A single writer and shared inference lock serialize
designer/researcher use of the same resident model.

The English existing Foundry/Workbench offers explicit loss, method and budget,
validation and fresh request-bound compute consent. Viewing/importing/editing
does not run or adopt an institution. No automatic same-society adoption occurs.
Blackbox1..8 and nested-lr exactly4 are the implemented UI/API budgets; arbitrary
nested schedules are not claimed. Stage updates, current/best, failures and
available exact generated sources/graphs are displayed without fake outcomes.

## Completion and analysis

Completion is the integrated executable flow and honest evidence within the
fixed budget, not discovery of useful institutions, gradient superiority or
an improved inventor. Independent read-only audit must rederive losses from
actual native checkpoints, reconstruct sampling/updates/source envelopes,
check all raw model replies/requests and literal code/graph changes, verify
physical scientist caches/wire records separately from authoring costs, retain
all failures/ties, compare source bindings and leave raw bytes unchanged.
Repeated audits must be byte-identical. Actual data, any SCRIPTED QA and any
preserved failed infrastructure starts are distinctly labelled.

Publish source-bound tests, actual figure/UI captures where available, logs,
goal map, manuscript and visually verified PDF, then non-destructive main
integration/push. No population/seed/horizon scale-up or whole-world derivative
is required. This finite goal does not predeclare all future research complete.
