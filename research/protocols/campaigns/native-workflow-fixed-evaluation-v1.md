# Selection-fixed workflow evaluation v1

Prospective software route, not a scientific dispatch or selection of seeds.
It depends only on a normally closed workflow development study and its two
unchanged cold audits, never on the stopped presentation comparison or old
unused three-study joint plan. Failed/unknown/stopped development cannot pass.

Freeze the exact original T-selected/U-selected own policies, all ties and
all-null outputs before new-condition observation. Keep both literal fresh
development controls, R7-original and hand post-funding-cost, as evaluation
references. One to three explicitly declared unused world seeds give at most
four physical policy worlds per seed; literal policy identity alone can share
jobs/labels. No own output is replaced with a reference or a new winner.

Only the supported initial-state seed binding changes. All native effects,
institution code, numeric parameters, phase/wiring choices, corpus/scientist,
T/U, critic rubric/decoding/centering, and any declared scientist transport
profile stay literal. The common observer's finite POST allowance may grow
from1500 to3000, not its rating instrument. Each native world retains1024 HTTP
attempts and7200s safe-point allowance; there is no designer POST or generation.
Known evaluation failures remain null and are not replaced or rescored.
Unknown responses stop all later evaluation jobs, not a scientific loss.

Require both original development and per-dispatch seed-inventory proofs;
recheck inventories before any evaluation start. No evaluation feedback goes
to design, selection, a new loss or seed choice. Evaluate every declared label
and seed, compare both scores against both controls, preserve paired outcomes,
all missingness and costs. Freeze evaluation criteria before dispatch; do not
choose only contrasts that look favorable afterwards.

Use seed-rebound anchors for actual native workflow interval witnesses and
the exact original phase/cashflow boundary rather than descriptive schedule
metadata or funding-stage summaries. Cold replay must reconstruct the whole
evaluation plan, original selected systems, runtime/source/role/transport,
each checkpoint/effect/critic/score and physical-job sharing. Repeated cold
reads/reports are not independent scientific observations or optimizer seeds.

Before any real dispatch, complete a committed-source SCRIPTED native full
path through the production evaluator, all-null and runtime-null cases,
source-bound original cold audit/cost/report interfaces and unused-seed guard.
Pure plan arithmetic is not that proof. This protocol chooses no actual
unused seed, adds no merit/participation veto, promises no institutional gain
and does not establish independent optimizer replication or publication readiness.
