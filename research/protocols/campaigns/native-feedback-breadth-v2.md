# Native feedback breadth v2 - small development integration

2026-11-01. Preserve the original researcher world; no scale-up or hidden veto.

Three implementation gates: (1) model-written source revision receives actual
loss/activity/checkpoint feedback and enters repeated fresh native evaluation;
(2) paired design-distribution gradient estimates use complete native-world
losses, including new fixed-model responses, not frozen trace-only losses;
(3) an English game UI can submit a versioned edited graph and explicit loss
to a loopback-only durable queue, then load actual completed evidence.

Source probe starts from the previously inert Peer Observer implementation;
upstream source is declared development input, not adopted new-source evidence.
Use fixed Qwen3:8b digest500a1f..., seed1301, five independent balanced authors,
two native years, original four-year cached SciEvo corpus, one inference worker,
and negative accepted-decision count. Budget: initial plus two result-conditioned
source revisions, at most three technical repair attempts per revision. An
inert or worse candidate remains valid and is not given a technical penalty.
Preserve every draft/error and evaluate only technically executable proposals.
No usefulness, topology invention or policy benefit is presumed.

Gradient probe uses explicitly declared continuous institutional coordinates,
one antithetic pair and the same native population/corpus/horizon. Estimate the
gradient of a smoothed design distribution, not a native pathwise derivative.
Equal costs may yield zero gradient; do not reroll for a nonzero result. Full
LLM input-response differentiation remains a separate unsolved gate.

UI submissions are explicit user actions, never triggered by viewing a page.
The server accepts JSON systems/losses, not paths, shell commands or credentials;
workers require clean pinned source and execute generated Python only inside
the existing no-network container boundary. Keep seeds from sealed historical
studies out of new UI jobs. Job creation and scientific execution are distinct.

All live runs start only after implementation/tests commit, in clean detached
experiment worktrees. New code is developed elsewhere. Record compact audits,
actual limitations and raw locators; no held-out or cross-probe method contest.
