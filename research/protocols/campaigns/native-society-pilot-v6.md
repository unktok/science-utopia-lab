# External institutional redesign within one persistent native society v6

Status: implementation/scripted-QA protocol; **no live inference authorized or
performed by this preparation**. A live run requires root authorization after
integration and a fresh clean, commit-pinned experiment worktree. This document
precedes any such execution. No existing experiment/raw evidence is modified.

## Question and deliberately small scope

Can a specialist observe an explicit objective and the actual original native
researcher society, author a new executable research-activity institution,
introduce it without resetting that society, observe its following interval,
then revise and observe once more?

This is a software/online-design capability pilot, **not a causal benefit test**.
Same-society sequential losses include time, previous decisions, research project
durations and random/model variation. They are not comparable to fresh common-seed
counterfactual trials, independent replicates, held-out superiority or verified
scientific quality. No scaling population/seeds for statistical significance.

The live CLI pins:

- Original `LocalQwenNativeFactory`: five balanced independent native researchers,
  seed1301, **three scientific years**, unchanged real corpus fixed at four years.
  Three years is the minimum to observe after two annual institutional adoptions.
- Fixed local `qwen3:8b` weights/digest, thinking false, max_tokens768, concurrency1.
  All native HTTP calls use the shared lab inference flock
  `/Users/shiro/unktok/dev/science-utopia-lab/outputs/native-parallel-v3-inference.lock`.
- Original scientific agents, corpus/RAG/paper production, review/publication,
  funding/resources and lifecycle. Initial `activity_world_system(seed=1301)`
  contains the original research world and exposes explicit research-plan and
  amendment capabilities. No initial host-authored allocation/planning policy or
  numeric miniature is inserted. The v5 resource bridge remains available.
- Initial engineering objective: existing explicit throughput `L=-A`, where A is
  actual accepted native review-history decisions in the **new interval**. The
  callable proposer/runner accept any explicitly declared one-society development
  LossSpec; objective choice is separate from algorithm, validity and consent.
- Two external design requests, one technical response per boundary; arbitrary
  complete Python/source/protocol/node/wiring patches within the pinned sandbox.
  No policy menu, missing-wire insertion, semantic source repair, quality/fairness
  floor, fabricated failed-run loss or silent extra technical draft.
- External authorship may be Codex or another explicitly identified author.
  Its metadata is self-reported, not authenticated provider identity. No paid
  provider API or local designer inference is invoked by the inbox/driver.

Every generated node must use the exact preregistered local container image.
This is an **execution-infrastructure pin**, not an institution catalogue or a
restriction to host-authored policy/source/wiring. Arbitrary algorithms, complete
Python bodies, protocols, node structure and wires remain externally authored;
the host neither fills them in nor changes them to make a candidate useful.

## Durable transaction sequence

1. Run the founding society through year1, save its complete portable checkpoint,
   then `NativeSocietyDesignSession.observe` measures the actual interval.
2. Publish a hash-addressed external request containing the exact current graph,
   source/model/corpus/seed/world binding, declared loss, prior observations and
   adoptions, actual domain state, pinned image and full activity contract.
   Missing response is a resumable **waiting** state, not technical failure/loss.
3. An external author supplies exactly
   `{request_sha256, manifest, authoring}`. Manifest has exactly
   `{patch,state_actions,discard_deliveries}`. Patch includes complete generated
   source, protocol and explicit graph edits; migration decisions are explicit.
   Authoring includes kind (`codex-agent`/`external`) and nonempty identity.
4. Rerun the original command: reopen the **same founding configuration/cache**,
   validate and restore the exact descendant checkpoint, consume only the exact
   hash-bound response and stage its unmodified complete design. Do not run year2
   until explicit consent to the **staged request hash** is recorded.
5. CLI `--confirm-request-sha256 <STAGED_HASH>` calls `session.confirm` just like
   the loopback UI. Confirmation records consent only. The saved-boundary native
   worker verifies it, atomically adopts via the migration API, preserves the
   whole pre-adoption society and advances that same society to year2.
6. Measure year2's new interval. Publish a second request with actual year2 loss,
   first adopted source/graph and complete history. The next authored revision
   again requires exact staged-request consent before adoption and year3.
7. Save/observe year3. Independently re-extract every interval's metrics/loss from
   immutable observed-society checkpoint archives. Verify migration lineage,
   authoring request/response/patch hashes and actual generated-code/native
   activity-effect events. Report all three losses without claiming improvement.

The external inbox request hash and staged adoption request hash are **different
identities**. Progress records show which one is awaited. A wrong consent hash
cannot install a proposal. The UI may record consent while the worker is stopped;
it does not itself migrate or advance the native society.

Before inference, the driver freezes `society-session-config.json` with the
server's five operator-owned fields (`directory`, `founding_system`, `loss_spec`,
`world_binding`, `checkpoint_directory`). The latter is the **actual** Simulation
output path. Identical restarts do not rewrite it; changes fail closed. Pass that
file to `scripts/serve_native_lab.py --society-config ...` to connect the existing
Continuity Spine. An external author/HTTP request cannot choose these paths. A
live browser consent→worker resume→verified saved receipt→completed UI capture is
a separate root-run acceptance check, not claimed by scripted tests here.

Every resume uses `runs/persistent-society/system.json` for the unchanged founding
graph. Native portable bootstrap verifies descendant migration lineage; the driver
never substitutes a newly initialized society, rewrites the founding graph, copies
a loss from another trajectory or reruns an independent baseline. Final terminal
reopens validate the completion/journal/archives read-only instead of needlessly
rerunning final-report/simulator startup. Intermediate saved-boundary/full-state
checks remain strict; no scientific snapshot check is weakened.

## Evidence and failure handling

`plan.json` freezes protocol/world/model/corpus/source/hash-seed/runtime image and
founding graph. Session events bind exact observed whole-society checkpoint hash,
kernel/event-prefix/domain hashes, loss and adoption receipts. The external inbox
retains exact requests/responses, canonical hashes and **raw file** hashes.
Duplicate JSON keys, altered consumed response bytes, changed binding and duplicate
adoption are rejected. Repeated waits/resumes are idempotent and do not add model
responses, native observations or migration receipts.

The native factory records actual HTTP payloads/response-cache evidence. The driver
explicitly installs a recording Docker executor even though the founding graph has
no code node, so institutions introduced later retain their actual input/output/
source/image/container receipts. All generated Python stays in the existing
networkless/no-host-mount pinned sandbox; no host exec/import fallback exists.

The read-only auditor independently computes eight interval metrics from actual
archive review histories and current native author stocks, and evaluates the
declared loss. It checks exact original portable contract across all years,
adoption receipt chain, source/image execution hashes and source-event ancestry
of actual research-plan effects. It also reconstructs the exact prior journal
feedback, loss, graph and domain hash delivered to each external designer, then
links its exact response manifest to the staged patch. It does not use the native
simulation measurement adapter or invoke models/containers.

Missing response/consent is expected waiting. Invalid source/graph/migration or
native execution failure stops with explicit null failed-candidate loss and no
automatic redraft. Preserve the response/source, last valid checkpoint and all
receipts; a new attempt requires explicit protocol amendment, not host repairs.
Plan-effect atomicity is per invocation, not whole-year rollback; failed years
must resume from the preceding portable checkpoint. Live effect or proxy benefit
cannot be inferred from scripted QA alone.
