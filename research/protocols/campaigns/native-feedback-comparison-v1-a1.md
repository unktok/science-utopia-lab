# Same-source objective-conditioned feedback comparison V1 A1

Prospective development pilot,2026-11-07. The user's instruction is to proceed
thoroughly with the publication research plan. This is a finite local-compute
comparison, not a scale-up, held-out confirmation or promised positive result.

## Fixed design

Original native world, five balanced independent researchers, two years, seed42,
four-year pinned public corpus. Qwen3-8B scientists retain their original model
digest/options and reply semantics. The already approved local35B designer uses
the bounded V45 profile,16 actions/candidate,8192 output tokens/call,40960 context
tokens, temperature0.6, no reasoning, source-owned10s connect/900s read timeout.
No model installation, remote provider, new machine or paid service.

Fresh `open_native_system` is the shared initial parent. No historical warm
start/cache or other-arm result is supplied to a proposer. Two existing losses:
throughput `-A`, and efficiency `-Q+0.5R`. These were chosen after development
experience; this is not a newly preregistered scientific hypothesis.

Two proposal policies per objective:

- `loss` arm (`matched-loss` controller policy): whole-history loss/measurement
  feedback and loss-selected incumbent parent. Native/compiler error messages
  are withheld; both arms receive the same exception-class channel.
- `technical-only`: fixed initial parent; own authored definitions/candidates in
  chronological order; exception classes and technical completion states only.
  No measurements, losses, native error text, raw outcome IDs/hashes, selection
  labels, optimizer reports or loss-adapted strategy statistics reach the author.
  The objective definition stays visible. Technical success/failure can itself
  be informative about the world; this is not a zero-information control.

This compares the adaptive feedback package (including parent selection), not
only exposure of scalar scores. Authored source/provenance remains literal own
data. Trusted callbacks can access their caller's environment: this information
boundary is not a security sandbox for adversarial host code.

## Finite budget and sequence

Exactly two proposal slots/arm; eight total. Generations G0 and G1 each execute
arms in fixed order: throughput-loss, throughput-technical-only,
efficiency-technical-only, efficiency-loss. At G0 there is no prior outcome; G1
is the first feedback comparison. No statistical replication claim.
G0 proposals are separate designer calls, not a shared proposal or a common
designer-response prefix. Sharing the world seed does not make their designer
sampling seeds identical or establish a paired causal effect of scalar feedback.

One fresh baseline native world is measured separately, then the same forward
measurement vector is scored under both declared objectives. The common world
experiment binding has no objective/arm input. Baseline outcomes are not passed
to either proposer, so initial information is identical. It is an evaluation
reference, not an extra feedback observation. At most nine native worlds and
128 authoring POSTs; failures consume slots, never refill. Calibration ≤40 POSTs
and its one designer load are separate. Each proposal explicitly loads its
designer at most once; each constructed world loads its scientist once.

Actual source commit, protocol hash, runtime/model/backend, image/corpus,
decoding/timeout, initial system and full campaign bindings are frozen in
`plan.json` from a clean detached experiment worktree before inference. Source
must pass committed-source software tests and fresh execution-readiness-v39
calibration/cold replay. A failed/stale certificate stops dispatch. No historical
failed certificate is relabeled. Calibration success is technical evidence, not
free-invention capability or guaranteed future capacity.

## Outcomes and interpretation

Store every candidate/action, exact bytes, definition, full observation,
measurement, null/error, checkpoint, scientist request/reply and code receipt.
Technical-only data are explicitly projected; internal evidence is not altered.
Report own-arm paths, all ties, baseline comparisons, and every candidate's
cross-score under both losses. Also show pooled loss-only best independently
of generating arm; labels never veto an otherwise eligible candidate. Failure
stays null rather than a bad numerical score. No hidden quality/novelty/fairness
filter or positive-improvement termination rule.

Separate logical candidate/oracle counts, physical worlds/replies, designer and
scientist tokens/seconds, loads, containers and audit costs. Equal oracle slots
are not equal total computation. Use actual recorded elapsed time; prior V45
17minutes for two proposals is only an approximate feasibility reference, not
a promised nine-world runtime.

First analyze differences and proxy mechanisms. A one-seed/two-generation pilot
does not establish optimizer superiority, causal scientific-policy benefit,
real quality, generalization, recursive self-improvement or a publishable paper.
Freedom ablations, independent unused conditions and further literature analysis
remain separate next work. No change/retry is made inside the frozen campaign.
