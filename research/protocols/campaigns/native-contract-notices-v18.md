# Conditional code contract notices on archived candidates

## Scope

The V17 native feedback goal remains unmet. This continuation adds a
nonblocking diagnosis of one observed runtime error before spending more
inference. It does not authorize another optimization pilot, a different
designer provider, researcher training or world scale-up.

V17 a2's changed candidate declares the selection `scores` payload schema as
an array. The current code ABI supplies object payloads inside a list of
records. Static validation accepts the schema, but the first actual object
delivery fails at runtime. The new notice describes that conditional mismatch
without modifying or rejecting a candidate. Empty input/output record lists
remain legal; returned state is always an object when code executes.

## Implementation and verification

Inspect explicit root-level schema `type` declarations for current version-one
`code.python.v1` artifacts, including process-wrapped delegates. Unknown
implementations/versions and implicit/composed types are not treated as solved
schema satisfiability problems. Nested array data inside object payloads and
unions permitting objects do not trigger the notice. Warnings retain exact
paths and authored types; no schema, path, code or objective is repaired.

Surface a bounded notice summary during static validation and in the draft
index. Keep validity, candidate eligibility and the authored candidate system
unchanged; runtime provenance hashes necessarily identify the new source.
The source change invalidates old runtime-bound certificates as
usual; no new production call may reuse those certificates.

From a clean, committed analysis checkout, use the existing source-matched a2
audit to verify every raw-file hash before reading the archive. Analyze both
archived candidate documents, not just the failed one. Inspect all archived
designer POST role envelopes to test whether the trusted protocol, ABI and
objective directive already reside in SYSTEM. Do not infer model compliance
or the cause of planning failures from the existence of those instructions.

Run the read-only analysis twice with fresh outputs outside raw evidence and
require identical results. Recheck the raw inventory after each analysis.
Record the original actual source separately from the new diagnostic source.
Portable tests cover notices, empty-port legality, non-veto finishes, version
boundaries, missing POST coverage and concurrent raw changes.

## Finite compute boundary

This protocol permits zero new model POSTs, zero scientific worlds, zero
generated-source executions and no change to archived outcomes. Read-only
hashing, JSON inspection, static/data validation and SCRIPTED tests are not
scientific simulation results. A useful warning is not proof that the local
author will use it. The full two-objective/two-generation goal stays open.

The separate external-Codex designer choice is still unanswered. Do not
substitute that provider or silently extend a completed V17 generation budget.
