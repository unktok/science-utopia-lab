# Different objectives for freely authored native institutions

## Decision and present status

The next experiment will optimize the institution under two declared objectives:
publication count and fixed content utility. It will not repeat unchanged T/E,
require a topology change, or treat successful execution as publication readiness.
The four resource controls establish a consequential native action at base30;
the fixed-content readout establishes support for a separately declared preference.
Neither supplies the answer to this new optimization question.

This is the prospective implementation specification, **not a frozen launch
plan or a running experiment**. Dispatch requires the source-bound runner,
actual saved-plan reconstruction, original-input test bank, calibrated designer,
auditor and untouched evaluation-seed check below. The next implementation work
is these connections, not additional source/metric brainstorming or more seeds
for the completed developer assay.

## Question and hypotheses

When the same designer can change scientific institutions, how does replacing
`T=-A` with `U=-sum(three-critic content mean - 3)` change its proposed rules,
information/resource routes, selected systems and persistent consequences?
U uses `native-common-content-utility-v1.json` and the existing fixed observer.
The center3 is its prior anchored rubric, not a coefficient fitted to make
particular institutions win. There is no review-cost, fairness, participation
or novelty term in either objective.

Different objectives need not select different systems. If observed optima
coincide, report that and examine the action/metric support. A candidate may
beat its starting point but lose to a simple reference; that remains a failed
strong-control comparison, not invented institutional superiority. New graph
syntax, critic opinions or this finite one-history experiment alone do not
establish an important main-conference result.

## Fixed world and allowed design

Retain the original five Qwen3-8B researchers, other native agents, original
2016--2019 corpus, four years, project durations, production, costs, grants and
activation. Use original balanced_two_band base30 and resource ledger enabled,
bound to actual founder proof. Development seed61001 is reused and named as such.
Researcher and designer weights remain fixed; use only the existing local35B
designer, pinned no-network executor and offline data.

Both searches start from reviewed accept-all with the developer whole-unit
liquidity program connected. Starting from a strong rule avoids making a weak
initial threshold the main comparator. Within the explicit fixed-production,
review-routing design domain, arbitrary institutional code, state, mechanisms,
entities, edges, protocols and institutional schedules remain editable. New
resource/selection/information mechanisms need not resemble this starting rule.
Original production laws, observer and world conditions are not candidate code.

Five fresh same-source developer references precede search: the starting
reviewed-all/connected policy; one-reviewer-all/connected; no-review-all/connected;
no-review-reject-all/connected; reviewed-all/disconnected. All retain the same
M1 information institution. The differing routing/transfer permissions remain
available to the free author; these are strong explicit rules, not discoveries.
Both authors receive the same declared developer reference context. Its actual
prompt retention must be tested, not inferred from a plan field.

## Finite development and costs

Two objective arms, four chronological proposals each: T/U, U/T, T/U, U/T.
Each proposal uses only its own history plus the common developer references,
not the other arm's later outcomes. The reference context includes both
declared cross-scores. The campaign minimizes its assigned scalar; the other
score is not an adoption condition. Preserve every generation failure, runtime
null, successful identity proposal and tie. No failed slot is replaced.
There are at most13 development native worlds: five references and eight
submitted proposals. A technical candidate failure consumes its slot; an
unknown model completion stops further dispatch. A failed reference stops the
development experiment rather than creating a substitute reference.

Each world has at most1024 scientist HTTP attempts and a7200s safe-point wall
allowance. Every history-bearing generation requires a fresh source/backend/
mode-bound real interface certificate: at most40 calibration POSTs per session,
1200s calibration and1800s proposal allowance, at most16 proposal POSTs. Count
all readiness, designer, scientist, observer and model-load events separately.
No new paid provider, weight download or silent timeout enlargement.

The original-input component bank must include successful recorded selection,
information-feature and pre-cost liquidity contexts from the fully audited
developer worlds, including empty cycles. Test exact edited code in the existing
container, persist observed errors with code versions, and declare the finite
probe budget in the actual worker contract. The prior worker hardcodes8 probes;
budget support must be changed prospectively and tested before a new value is
claimed. Passing fixtures never vetoes or guarantees whole-world execution;
unconfigured interfaces stay legal. No host source repair or hidden retry.

Use a fresh policy-blind three-position common observer for all development
worlds, capped at3000 physical critic POSTs. Cache exact content across both
arms/references so repeated content is not another independent rating. Preserve
all original base metrics. Missing panels remain unavailable; unknown completion
stops later inference. U enters actual adaptive loss and next-proposal feedback,
not merely a retrospective report. Never send policy, score, author or acceptance
labels to the observer. Its abstract opinions are not scientific truth.

## Selection and subsequent unused evaluation

After all eight slots close, freeze the minimum completed submitted loss per
objective, retaining all ties and selecting the earliest tied submission. An arm
with no completed policy stays unavailable; no seed/reference fallback. Freeze
the whole selected literal system, not only its favorable parameter values.

A separate evaluation then compares both available fixed selections and all five
controls at three world seeds unused in every checked project raw root: at most21
worlds. Choose and inventory the explicit seed IDs before dispatching development;
do not choose them after seeing search trajectories. The same source, corpus,
world laws, endowment and observer definition remain fixed. Changing initial
endowment is a later robustness question, not another unused seed.

Use a separate evaluation observer cache with at most3000 critic POSTs, keep its
scientific decode rule unchanged and withhold evaluation from designers. World
seed holdout does not imply unseen literature, a new judge, independent critic
errors or independent search histories. A repeated content panel is not another
independent scientific observation. This finite design establishes policy-level
comparison, not a ranking of optimizer families.

## Required analysis

Retain all eight proposal paths and13-or-fewer physical development worlds,
selection ties/unavailable arms, both cross-scores, A/Q/R, fixed content ratings,
actual annual activity/resources, native transfer legs and real received contexts.
Join by identity, never positional arm order. Explain which source, state,
node, edge and schedule changes have actual consumers; do not implement prose
or require novelty. Compare to every strong rule on the assigned objective.

Independently reconstruct original physical execution, adapter contract and
literal critic pooling from raw records. Export all cases and figures twice;
preserve nulls and missing costs. Then analyze the selected systems on unused
world seeds before drawing policy claims. An ablation of a discovered mechanism
needs its own prospectively fixed intervention; source differences and outcome
differences alone do not identify that mechanism's causal contribution.
