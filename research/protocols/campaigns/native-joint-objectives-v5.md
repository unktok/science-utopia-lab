# Objective-conditioned native code and graph search v5

Preregistered 2026-11-01, before v5 joint-search forward execution.

## Question and scope

Does changing an explicit loss change the generated institutional algorithms,
internal protocols/process graph, and subsequent result-conditioned revisions?
The forward simulator is the original researcher world, not a miniature numeric
substitute. This is a development pilot, not held-out evidence of science-policy
value, algorithmic novelty, or statistical superiority. Population, horizon and
replicate scale-up are deferred.

## Fixed budget and objectives

- Qwen3:8b, fixed researcher/designer model weights and recorded model digest.
- Five independent balanced researchers, one conference, two simulated years;
  four-year frozen corpus. Development seed1301 and process PYTHONHASHSEED42.
- Two explicit losses: throughput `L=-A`, net-reviewed-utility
  `L=3.25*A-Q+0.05*R`. A is actual accept decisions, Q is the sum of the actual
  raw reviewer-score means of accepted decisions, R is actual review records.
  Generated `final_score` does not determine Q. Empty review sets contribute
  Q0; malformed existing review scores make Q unavailable, not an invented0.
- These coefficients are declared engineering preferences. The second loss
  charges for publication and review; it is not a hidden acceptance threshold
  or a claim that peer scores measure scientific value. A reject-all solution
  is legal if that is what this declared proxy rewards. No fairness, activity,
  quality or promotion veto is added.
- Objective selection is not blind to earlier development evidence: the old
  source-only v3 probe had raw review means3. The publication charge3.25 was
  chosen before v5 to make an explicit competing preference visible at small
  scale. Thus a contrasting ordering is an illustrative engineering test, not
  an independently discovered normative trade-off or held-out hypothesis.
- Each arm: one initial system plus **two** adaptive proposal slots. Each slot
  permits at most **three** technical drafts, temperature0.2,4096 output tokens.
  Invalid draft loss is null. Exhaustion halts that arm, preserving receipts;
  there is no silent fourth draft, replacement trial or selection by success.
- One original physical baseline trajectory is shared by explicit logical
  adoption after independently checking checkpoint bytes/measurements and exact
  system/world/seed identity. The two baseline rows are NOT independent runs.
  Maximum fresh physical worlds: five (one common baseline + four candidates).

## Search freedom and compilation

Start from the developer-authored rank/rate Python selection slot; all original
researcher, project, review, publication, funding and history mechanisms remain.
For this first joint pilot the declared editable cut is the selection region,
not the expression ceiling of the graph runtime. The designer emits arbitrary
Python, freely many internal nodes within the explicit1..6 budget, novel typed
internal protocols, explicit source connections and exports, and execution order.
Node names are local, then hygienically scoped; ordered phases are mechanically
allocated inside the real external cut. The compiler does not supply missing
semantic wires, choose an institutional algorithm or rewrite generated source.

Actual parent code inputs/outputs are recorded, with source/image/event bindings.
All chronological frozen-boundary periods are technically probed; real paper
coverage/decision schemas/publication signals must remain executable. A probe
pass is NOT an objective observation. Each eligible child is freshly executed
through the original native world; fixed LLM weights do not freeze its outputs.
Next proposal receives the exact loss, actual measurements and prior losses.
Best completed declared-loss observation is the next parent (first on ties).

## Persistence and independent evidence

Use a clean commit-pinned experiment worktree, separate from development. Exact
prompts, generated drafts, repairs, source, JSON graph, input bundles, checkpoints
and response journals remain local/ignored; compact manifests and results are
tracked. All lab inference uses the same explicit single-request flock as the
parallel fresh-native policy-gradient pilot. Shared queue contention is part of
wall time, not model throughput. Separate arm caches bind the full objective and
experiment protocol. A crash resumes saved drafts or native checkpoints; it does
not silently consume a new proposal.

`scripts/audit_native_objective_v5.py` independently reconstructs actual native
checkpoint metrics, verifies external checkpoint hashes, source/model/corpus/
seed/code receipt identities, re-evaluates declared losses and cross-scores each
executed system under both objectives. Search curves show logical rows while
reporting unique physical worlds separately. No additional held-out run is
authorized by this pilot. Failure is a publishable engineering result, not a
reason to report an unexecuted institutional design as effective invention.

The parallel policy-gradient pilot is a separate experiment with its own source,
two prerecorded draws and fresh complete native costs. Its probability update
does not imply an input-response Jacobian through the LLM or a pathwise gradient
of the entire native society, and is not merged into the joint search results.
