## Question and competing explanations

Does exposing an institution designer to actual longitudinal native resource,
production and execution observations change the institutions it submits and
their consequences, compared with the same open author given scalar losses?

The actual open v2 T0 rewrites the already accept-all selector and claims
optimality, while another measured hand policy attains20 rather than18 outputs.
The hand is intentionally not optimizer-visible. That does **not** identify
lack of observations as the cause. A designer may fail to understand visible
source, fail to generate valid code, find no useful reachable change, or remain
limited by this world's production/objective support. More repetitions of
unchanged scalar prompting would not isolate these explanations.

This study would intervene on **designer observation access**, not institution
authority or graph syntax. Arbitrary code, nodes, wires and schedules stay
identical in both arms. An institution may legally remain simple or unchanged.
A trace-arm advantage, if observed, would not prove graph representations
necessary, a new optimizer, scientific truth or an isolated benefit of freedom.

## Implementable observation boundary

The existing ResourceLedger stores closed annual opening/closing resources,
active flags, all collected category amounts and unexplained residuals for
each original author. Native events record actual annual phase order. Portable
checkpoints retain those data alongside real projects and paper origins.
These are available sources, not an already connected author feature.

A new optional measurement/author/cold-reader profile would need to project:

1. Per-year original-author opening/closing balances and activity, collected
   grant/cost/transfer categories, and reconciled residuals. No within-phase
   resource vector is guessed from an observation hash.
2. Actual protected native phase execution order and event counts, with literal
   reference to the submitted system and year; no host advice to move a phase.
3. Actual native project start/end/duration, production/submission/acceptance
   counts by year, using original tracker/checkpoint semantics. Counts of
   unique contents and decision occurrences must remain distinguishable.

Use fixed fields independent of size/outcome, retain full source hashes, all
own scalar values/failures and the exact parent. Keep original content-panel
bodies and arbitrary institution-generated prose outside both observation
profiles. Do not select only surprising events, substitute host causal labels,
invent missing annual states, expose unused-condition outcomes or silently
truncate a large frame. An explicit cap failure is technical missingness.
Cold audit must reconstruct the same feature from original persisted evidence,
not merely trust a designer-facing summary attached by the running process.
