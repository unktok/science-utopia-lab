## Why this changes the next research decision

The [first two original author traces](../results/native-consumer-source-first-two-author-traces-v1.json)
finish normally before their step cap. Their candidate losses tie the strong
parent. The second plan proposes the parent's already installed topic policy,
and its only source change is formatting. These observations motivate testing
the **search procedure**, not merely counting valid code or adding evaluation
seeds. They do not identify a causal explanation for the author's choice,
exonerate every software path, or predict the remaining six outcomes.

The current procedure selects the minimum-loss visible/own parent and retains
literal archives for reading. Retaining all records is not the same as sampling
non-incumbent programs as parents or giving multiple inspirations to a proposal.
Likewise, the source-information treatment changes information, not the parent
sampling rule. This is a distinction between implemented methods, not a claim
that an archive sampler must work better.

After the original finite pilot and its paired closure, use its complete
evidence to decide whether a prospective comparison is justified:

| Candidate comparison | What it isolates if all other contracts are held fixed |
| --- | --- |
| Fixed-parent independent proposals versus greedy feedback | Does using own outcomes/history help beyond repeated proposals from the same visible strong starting point? |
| Greedy feedback versus declared archive-parent sampling | Does access to non-incumbent stepping stones change proposals, operative behavior or assigned loss? |
| Same free authority versus an explicit parameter family | Does the tested end-to-end search exploit added freedom beyond a strong, named restricted family? Not a universal proof about expressivity. |

These are alternatives to prioritize, not three newly scheduled experiments.
Do not combine changes to parent selection, source cards, model, editing ABI,
search temperature, history display and world authority and label the result
an isolated effect of one change. The information pilot must first close; a
new study needs its own immutable plan and exact source, finite allocation,
software proof, real readiness, strong same-authority hand controls, independent
histories appropriate to its claim and frozen unused-condition evaluation.

Any adopted sampler must depend only on declared development observations.
Keep all consumed proposals, including unchanged, null and adverse candidates;
choose final systems under the assigned loss, not novelty. Do not import
embedding/LLM novelty rejection or a scientific-merit veto from another method.
Changing exploration probabilities is an explicit optimization-method choice,
not a change to the scientific loss. No host-authored replacement code fills a
missing proposal and no failed slot is replenished.

Count candidate attempts, worlds, author/readiness/load POSTs, measured tokens,
probes and shared-host time separately. Equal proposal counts are not equal
measured compute. Distinct policies, repeated audits, component tests, content
panels and extra evaluation seeds are not independent optimization histories.
Unchanged observed paths are useful evidence, not proof that no other system
can improve. The current known terminal hand comparator remains a disclosed
strong control, not an unseen discovery for us.

## Consequence for the manuscript

The intended contribution cannot be simply code generation, an evaluated
archive, graph search or feedback-driven optimization. The supported scientific
answer must concern how a declared objective and organizing-system search
change a persistent native researcher world, with measured actions, losses,
costs and suitable comparisons. A null from one short local search is not
automatically an important general result; recovering known accounting headroom
would not by itself establish the stronger answer either.
