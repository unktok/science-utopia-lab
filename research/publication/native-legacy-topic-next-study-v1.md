# Prospective next study: reachable original actions, then objective-conditioned search

## Question and reason for this change

The project asks which executable organizing systems are found under different
declared losses, not how to tune a peer-review menu. The closed local searches
mostly edit an already all-accept selector. This is an observed concentration,
not a proven cause. The original-choice pilot then exercises the original
core-plus-related researcher route, but advice does not induce any one-year
selection and does not beat direct core assignment. Changing T/U weights or
adding seeds to the same measured policy bank cannot create an unobserved
tradeoff. Resource measurement now supplies a distinct measured axis, but its
retrospective algebra is not objective-conditioned optimization.

There is a concrete authority mismatch to resolve before the next study:
`native.catalog-project.v1` validates only core expertise, while the original
non-strict researcher resolver permits core plus directly related topics.
The general `native.project` already permits broader modifications, but the
historical fixed-effect studies exclude it because it can change durations or
ongoing projects. This is not a claim that the overall platform lacked project
expressivity, or that this mismatch caused the earlier local designer failures.

The new `native.legacy-topic-project.v1` exposes the original permitted union
while preserving exact original catalog content/duration, idle/active eligibility
and original project/research/submission/funding/cost consumers. It neither
invents topics nor changes scientific production. The whole-system language
still permits authored code, new institutions/protocols, wiring and schedules;
this is not a replacement of free design by a fixed menu. The finite new
fixed-effect scope is explicit; it is not the global limit of the project.

## Implementation boundary

- New typed action and validation event; old core-only action stays core-only.
- Explicit `fixed-native-effects-legacy-topic-workflow-v5`, retaining all original
  effect, data-causality, image, initial-state and annual-ledger conditions.
  Old scopes reject new grants instead of gaining authority implicitly.
- Neither runtime nor domain demands shortest duration, improvement, novelty,
  fairness or a minimum activity level. A legal nonshortest original topic is
  accepted. Technical failures have unknown loss, never a merit penalty.
- Native cold reconstruction verifies actual project effects, before-state
  expertise, original catalog identity, exact eligible union and full assignment.
- Developer comparison rules receive the **same broad action permission**;
  only their source-controlled core-only/core-plus-related topic rule differs.
  Their common source chooses shortest duration for this diagnostic, not as a
  runtime requirement or a discovery claim. Future authors can replace it.

Limitations remain: topic content is an existing catalog, scientific activity
is still the simplified original model, effects need implemented native
contracts, and this domain retains one annual invocation per outer node with
bounded processes inside. No world-level AD or model learning is introduced.

## Finite next steps, not completed experiments

1. **Software construction.** Two original four-year native worlds, scripted
   scientist HTTP/corpus, real pinned Docker code, ledger, checkpoint and double
   cold physical proof. Demonstrate actual related-topic assignment, unchanged
   original duration/content, rejection of corrupted cold witnesses and refusal
   by old domains. Source must be committed/clean before this check. Software
   outputs are not scientific feasibility evidence or optimizer discoveries.
2. **Prospective real control feasibility.** Prepare a separate finite protocol
   before any dispatch: two developer controls, same original-world parameters,
   Qwen3-8B scientists, initial society/seed, authority and existing T/U observers;
   resource K reported separately. Both must execute at a fresh pinned source.
   All scheduled outcomes and costs, including failures and unfavorable losses,
   remain, without refills or repairs. This is a hand-control study, not a
   preregistered blind hypothesis or an optimizer effect. No real run is
   authorized merely by this document's existence; the runner's declared
   model/backend/source/finite-budget contract must first be completed.
3. **Objective-conditioned free design.** Declare explicit objectives, their
   scientific interpretation, budgets, parents, feedback exposure and selection
   before authoring. Use the whole source/node/wiring/process domain with strong
   same-authority controls. Cost weighting, if chosen, is a new study, not a
   replacement for old T/U; choosing weights from development must be disclosed.
   Do not require different winners or a positive outcome. The changed native
   source/new scope requires fresh actual designer interface/capacity binding;
   no historical certificate is relabelled.
4. **Publication evidence.** Match any method/generalization claim with adequate
   independent histories and selection-frozen fresh evaluation; add operated
   mechanism contrasts where they answer a causal claim. Merely attaining a
   hand-computed schedule, adding another control or passing the software path
   does not close R2/R3/R5/R6. The final main-paper claim must add insight beyond
   elementary shortest-duration or always-accept incentives.

No new loss is adopted, no reserved unused condition is examined and no model
call is made by this design note. Historical studies and the91-page PDF remain
literal. We will not scale up an unchanged unsuccessful search by default.
