# Prepare a native numerical optimization comparator

The free-program studies must be compared with effective simple optimizers,
not only isolated hand-picked rules or a weak initial threshold. The ongoing
[parent-presentation study](../components/native-parent-presentation-loop-v1.md)
keeps its fixed protocol and runs independently of this preparation. No new
numeric baseline is dispatched or added to that study.

## Existing operative parameter and old search coverage

The actual [capacity allocation program](../../utopia/system/native_capacity_controls.py)
reads `context['parameters']['reserve_units']` and emits conserving native
transfer commands. The existing controls already use10 and21; these are
developer choices, not physical constants or generated discoveries. Its
`allocation_rule` is categorical and is not silently represented as a number.

The old six-coordinate parameter domains cover selection, memory and
information parameters, not this allocation reserve. That is a limitation of
those declared numeric comparators, not evidence that the wider free-source/
graph domain cannot change reserve or create another resource institution.
The old constructors and finished experiments stay unchanged. A field's
presence in a schema does not establish its consumption or a loss effect.

## Implemented adapter

[NativeParameterSpace](../../utopia/optimization/native_parameter_space_v1.py)
accepts an explicit existing-coordinate contract and produces complete native
SystemSpec values. It samples or mutates only those fields and retains all
source, wires, schedules, metadata and other parameter values. The original
native law scope can be retained explicitly. It neither creates a consumer
for a dead parameter nor modifies a received model submission to make it fit.

The adapter works with the existing scalar ask/tell API. Its companion
NativeParameterOptimizer uses the existing adaptive random search, not a new
optimization method. Uniform initial samples are followed by bounded uniform
mutations of the best completed observation. Known invalid/failed outcomes
retain missing loss, never an artificial penalty. Exact serialized-space
identity is checked on restoration, including when the caller uses the
existing sealed-journal API. This is not an authenticated event history or a
complete native campaign proof; loss, model, corpus, source, world, seed,
budgets and actual measurements must still be bound by the experiment layer.

The tests' reserve range1--40 and synthetic scalar feedback are interface
fixtures, not a frozen scientific search range, a simpler replacement world
or evidence that a particular reserve improves native science. The first
62-case scope passes14.26s; additional float/serialization and malformed-input
checks expand that to67/13.51s and77/14.18s. These scopes overlap. A separate
isolated consumer test is provided to check that the emitted actual native
program's commands change while its resource total is conserved.

At committed9031064a, that isolated check and its older capacity-rule controls
pass seven tests in2.508s: four actual sandbox executions, without model calls.
Reserve20 sends2 units to `soon`; reserve21 sends1 to `near`, from the same
synthetic62-unit input. Both conserve62. This is consumer evidence, not a
completed scientist trajectory or an observed loss improvement. The
[immutable preparation receipt](../results/native-parameter-space-preparation-verification-v1.json)
retains exact source/JUnit hashes and separates the fixture bounds from any
prospective scientific range.

## Decisions required before a scientific comparator

Declare which system family or families are numeric seeds. A parameter-only
domain freezes its nonnumeric architecture: copying the best arbitrary common
reference into an incompatible anchor is not a valid numeric edit. Either
freeze a named strong family upfront or declare how the fresh common-bank
winner becomes its own numeric anchor. If the selected program has no such
operative field, report that coverage limitation; do not add a host consumer,
silently choose another parent or disguise a graph replacement as numeric
optimization. Different initial parents also prevent an isolated claim that
the only treatment is design freedom.

Choose bounds and proposal budget from the native parameter semantics and
resource/accounting support, not from the running study's partial outcomes or
a wish to manufacture different T/U winners. Count completed, failed and
unused slots explicitly. Internal avoidance of an identical unexecuted JSON
candidate is not permission to refill a failed native world or merge programs
merely because earlier losses or observed inputs matched.

Use the same declared T/U, original researcher world and same-authority fresh
references. Reusing a known development seed must remain explicit. Historical
results are background, not fresh bank measurements. A matched own-proposal
budget and a matched total compute budget answer different questions; report
both native evaluator calls and any model-author savings rather than equating
three program proposals with a large parameter grid. The method needs no
LLM author, but still needs the original scientist/critic execution contract.

Before dispatch implement the finite prepare/run/selection path, literal
warm-start policy if any, original native evaluation and cold proof, plus
source-pinned full-path software validation. No source/model/backend gate from
the live program-author study is reused as if it certifies that new campaign.
Analyze trajectories, final ties and outside T/U cross-scores, retaining all
failures. A good hand-coded comparator is not autonomous invention, and
optimizing this family does not exhaust the broader scientific-system domain.
Independent optimizer histories and unused evaluation remain distinct next
requirements for the publication goal.
