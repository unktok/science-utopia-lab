# Separate planning authority from the flat capacity search

The closed capacity pilot supplies no generated-policy advantage: its three
complete own programs largely preserve the reserve allocation parent. It also
does not grant `native.project`. Those facts cannot distinguish a world in
which no better organizing system exists from a search that explores only
equivalent policies inside a restricted domain. More evaluation seeds of those
same programs would not resolve that distinction.

The next research step is a small mechanism-support comparison of **institutional
research planning in the original world**, followed by a separately fixed
objective-conditioned search if the comparison establishes a useful question.
It is not a reopening of the closed pilot, a repair of P/g1, a new definition
of T/P or an automatic-invention claim for developer-written controls.

## Existing implementation and authority boundary

`utopia/system/native_open_domain.py` already implements `native.project`
through `native_activity_contracts._validate_plan`, actual native project
state, atomic effects and causal events. The developer structural example
demonstrates composing planner, protocol, command and native-effect nodes.
By contrast, `native_fixed_production_domain.py` explicitly rejects granting
`native.project` in the fixed-production and review-routing scopes used by
the recent searches. Adding this authority must therefore be a named new
scope, not removal of the old guard or a claim that the pilot already had it.

Preserve original researchers, fixed model weights, corpus retrieval,
publication production, accounting, funding capacity and native calendar.
Before any actual run, distinguish choosing a valid research project from
rewriting what counts as completing one. A control must use an existing topic
with its actual catalog duration; it must not turn a long project into a
one-year project by relabelling its duration. Existing unfinished work is
preserved unless a separately explicit interruption rule and its costs are
part of the design. Do not fabricate scientific outputs or native flags.

## Minimal comparison to implement and freeze

Use the same small capacity condition and the explicitly reused development
seed61001, not a newly labelled held-out seed. Construct a common explicit
agenda artifact from actual available catalog entries. A deterministic
shortest-permitted-project rule is a developer diagnostic, not a new method.
Its tie rule, eligibility and observed information must be fixed before use.

Compare at most three newly executed worlds:

1. Cut the agenda's effect while preserving the common observation path.
2. Deliver the same agenda as information to the original researchers.
3. Apply the same legal agenda through the existing native project action.

These differ in actuation, not only graph syntax or message timing. The
current strong reserve allocation rule and all native world settings remain
common. No new fee, grant pool, paper-output law or hidden acceptance condition
is added. All conditions run freshly under one source; an old pilot world
does not stand in for a new matched control. Report extra work/input/call costs
caused by the intervention, including any skipped or additional model choice.

The finite scientific ceiling is three worlds, each at most1024 scientist
HTTP attempts and7200 safe-point seconds, with zero designer/critic proposal
calls and no replacement of known technical failures. Exact source-bound
prepare/run/audit plans, catalog provenance, native-law checks and successful
full-path software tests must precede dispatch. This design note is not yet
that executable protocol or a claim that any of the three worlds is running.

## What determines the following experiment

Trace agenda creation, actual native recipient, project start/end state,
original scientist choices, production, costs and the unchanged T/P values.
The earlier advice null cannot substitute for the information arm: its
literal message and world conditions are different. An assigned project and
an obeyed suggestion are also different treatments, not two names for the
same policy.

If actual planning reaches its consumer and changes relevant native outcomes,
use that evidence to specify strong same-authority planning/allocation
controls and a finite free-source objective-conditioned search. The local
designer may retain a parent, introduce new institutions or wire processes;
none is required to be novel or win. A subsequent search, not the developer
comparison itself, must establish generated institutional design and its
relation to objectives. Independent optimizer histories and selection-fixed
unused evaluation are then planned from a concrete effect and measured cost.

If outcomes stay flat, determine whether the actuation changed the intended
projects and whether native production consumed those changes. Preserve that
answer before selecting another question. If the implementation has an actual
connection bug, keep its failed run and fix a future source separately; do not
repair generated policies or silently weaken an old domain. No result in
this note is a new empirical finding or publication-ready judgment.
