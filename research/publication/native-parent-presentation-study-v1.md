# Test parent presentation in objective conditioned institution search

Implementation update: the [finite native runner and cold readouts](../components/native-parent-presentation-loop-v1.md)
pass a corrected614.34s SCRIPTED20-world full-path test. The actual experiment
starts at November14 00:16JST from frozen30e3f5fa and first enters real initial
calibration. The [launch receipt](../results/native-parent-presentation-launch-verification-v1.json)
does not claim completed actual readiness or scientific effects. The design
below defines the comparison; it is not rewritten in response to partial outcomes.

The closed planning study establishes an executable native search, but all
six submitted edits target selection from parents already accepting every
paper. It does not establish whether parent presentation, loss incentives,
limited proposal capability or an actually strong parent explains that narrow
neighborhood. A useful next experiment must distinguish those explanations
without making novelty or improvement a requirement.

The next finite comparison changes **the information presented at the first
planning call**, not the permitted institution or the loss. This is a pilot
of a presentation package, not proof that source visibility alone causes a
particular reasoning process. A null result is retained and may show that this
specific package is insufficient; it cannot establish that better institutions
do not exist.

## Observations motivating the comparison

The [closed six literal plans](../data/native-planning-objective-loop-v1/initial-plans.json)
contain hypotheses that the editing parent has a lower score or rejects work,
although its exact archived request selects a strong all-accept parent. The
current bounded interface deliberately omits literal source on its first
planning call. It shows graph structure, common reference scores, virtual
filenames and operational order; exact source and the request are retrievable
afterward. Subsequent editing calls already show the full current document
when it fits the existing65,536-byte active-document limit. Those facts do not
prove that the omission caused the final edits: the original authors did read
source during implementation, and changing it may still be a rational choice.

The observed parent documents occupy59,762 bytes for U and60,413 for T in the
six original requests. Original first-call prompt bodies occupy89,323--95,864
UTF-8 bytes. These are measured bytes, not token estimates. The proposed
treatment substitutes the literal document for its redundant structural
projection and adds an exact parent-observation join. Actual provider token
counts, output completion and the reserved output allowance still require
fresh real-backend calibration.

## Presentation conditions

Control uses the existing bounded first-call view: structural projection,
unchanged scores and on-demand exact parent files. Treatment enables the
explicit strategy field `planning_parent_presentation` with value
`literal-parent-and-observation-v1`. It presents the complete unmodified
current parent and identifies its exact already measured observation by
`based_on_observation_id`, checking literal candidate equality in both the
suggestion and observation. It repeats that observation's loss and recorded
measurements without rescaling, rerating, ranking extra policies or interpreting
source. The initial unobserved calibration parent is explicitly labelled
unobserved, without an invented baseline loss.

No interpreted claim such as "this is accept-all" or recommended next edit is
supplied. Untrusted source remains in user data, never system instructions.
Planning tasks, editor actions, component tests, recovery/finish checkpoints,
model weights, decoding, archive access and remaining implementation calls are
the same. Later calls use the original view in both conditions. The treatment
is not a code repair, a forced graph change or a different loss. It fails
visibly rather than silently reverting if its literal parent exceeds the
declared active-document or wire budget; such differential technical failures
are part of the package's observed cost and usability, not grounds for refill.

Execute the same eight strong references freshly under the new pinned source.

T/control, T/literal, U/control and U/literal, each with three proposal slots
and optimizer seed68011. Parents are selected by the existing best assigned

feedback-bearing search effect, not an isolated first-plan intervention.
Use fixed per-generation order T/control, U/literal, U/control, T/literal
at generations0 and2, and its reverse at generation1. This balances presentation
and objective positions but does not make model randomness identical or
provide independent optimizer replication.

The ceiling is20 native worlds: eight references plus12 own slots. Preserve
1,024 scientist HTTP attempts and7,200 safe-point seconds per world. Allow a
shared maximum3,000 critic POSTs, three ratings per exact accepted content;
raising this technical ceiling does not change the instrument. There are two
initial readiness sessions, one per presentation, before any reference world,
and12 fresh history-bound readiness sessions. Each retains40 POSTs/1,200s.
Each own proposal retains16 POSTs/1,800s and64 historical component probes.
Record the transport's existing explicit finite connect/read allowances in
the executable plan before dispatch. Read timeouts, unknown completions,
model loads and known token counts remain separate from scientific losses.

Every known proposal, runtime or measurement failure consumes its slot with
missing loss. An unknown dispatch, failed readiness or failed common reference
stops later inference without repair, replacement or baseline substitution.
For each history, final selection is the earliest tied completed literal own
submission, or no selection; all ties remain visible. A new node, broader edit,
loss improvement or different selected policy is never an eligibility rule.
No real dispatch is authorized by this design note alone: commit-pinned
prepare/run/replay/audit logic and successful exact-path software checks are
still required, followed by the two initial actual backend certificates.

## Outcomes and the following research decision

Primary descriptive results are every loss trajectory, technical null and
selected own loss relative to all fresh same-authority references, with T/U
cross-scores. Report literal edit support, changed consumers, observed complete
scientist inputs and native actions separately. Greater edit diversity alone
is not optimization success. Nor is a plan claiming to understand its parent
evidence that the model does so. Complete input equality is evidence on the
observed path, not a general equivalence theorem.

Compare the two assigned-loss selections within each objective. Any differences
include the literal-presentation package, its extra input cost, proposal
randomness and divergent subsequent histories. One history per cell is a
targeted pilot, not a method-general causal estimate or independent replication.
The previous completed study is background, not a concurrent control arm.

If the literal arm explores different active operations, analyze actual native
loss effects and whether those changes explain the selected policy comparison.
If both arms remain narrow, distinguish effective objective support and strong
parent effects from proposal limitations using declared operator/parameter
comparators, rather than requesting novel-looking code. In either case,
independent optimizer histories and selection-fixed unused evaluation must be
planned around the question the pilot actually resolves. Do not run until a
win or create a new metric to manufacture disagreement. This comparison alone
does not close publication readiness.
