# Non-scale limitations relative to the intended research system

Updated: 2026-10-31. This inventory deliberately excludes bigger populations,
more seeds, longer runs and larger search budgets. Those cannot repair the
abstraction/integration limitations below.

The target is objective-conditioned design of an entire science system:
algorithms and institutional memory, which institutions exist, new protocols,
their processes and interactions, and researcher behavior. Parameters,
generated source, graph search and gradients are complementary design
freedoms/methods—not separate scientific purposes.

| Limitation / simplification | Current evidence and consequence | Next substantive change |
|---|---|---|
| Generated numeric rules used a fixed AST/operator catalog | Numeric program v1 has five researcher vectors and four effect dimensions. Changing an expression is not arbitrary institution invention. | New code route removes the algorithm whitelist; accept Python implementations, JSON memory and new output schemas. Test actual execution, not just parseability. |
| Code can emit a new protocol, but a consumer does not emerge automatically | Generated-code lab connects additional artifacts to a recording ledger. Storage is not a new institution or changed researcher response. | Jointly generate producer, consumer, schemas and graph patch; demonstrate causal state change downstream. |
| Integration harness still fixes the process | Generic SystemSpec can vary nodes/edges/delays/phases; numeric search does so. Code lab holds workload -> institution -> publisher/ledger wiring fixed. | Search source and arbitrary typed graph rewrites through the same evaluator; compatibility repair should not become a fixed node menu. |
| Semantic inputs are fixtures or synthetic numbers | Structural/code lab papers have predetermined metadata and review scores; numeric lab attributes and all quality transitions are hand specified. | Put generated institutions into the live researcher/artifact lifecycle and allow researchers to react in later periods. |
| Full original Qwen simulator is not a universal mechanism runtime | Native government/communication overlays and production adapters exist, but arbitrary node replacement is not a compiler target there. | A generic prospective lifecycle bridge, including persistence, delivery, researcher effects and checkpoint/resume; do not relabel adapter-only execution as the entire simulator. |
| World laws are fixed by us | Numeric quality, knowledge decay, production and effort equations were chosen for an engineering miniature, not inferred or validated. Code freedom alone does not validate them. | Treat world/agent models as explicit alternative assumptions and introduce richer artifact-level outcomes. Separate optimizing institutions from choosing favorable world laws. |
| Gradient design space is finite | Three rule choices per node, at most three orderings, fixed supergraph and delay interpolation. Program creation itself is not differentiated. | Learned/tensor-backed mechanisms, richer process parameterizations, and explicit surrogate/score-function alternatives for discrete changes. |
| Hard projection can change the result materially | Previous burden example had relaxed-to-discrete loss gap about 0.164. Representative gradient checks verify calculus only, not fidelity. | Outer-loop optimize projected executions, measure where the surrogate misleads, improve relaxation/decoder rather than hiding the gap. |
| Arbitrary generated code is not end-to-end differentiable | Code route is black-box; loops/strings/hard branches/sorting generally break ordinary autograd. Qwen token generation stays outside it. | Explicitly distinguish true differentiable paths, surrogate gradients, straight-through estimators and policy/score-function gradients. No claim that a generated institution makes the full ecosystem differentiable. |
| Loss/metric abstractions are not uniformly integrated | Original campaign uses LossSpec; Objective Constitution compiler is a prospective layer; numeric miniature uses local scalar losses; code demo intentionally uses trivial counts. | Compile explicit objective contracts into every backend's measurable inputs, retaining separate held-out diagnostics. Never silently add welfare/promotion vetoes. |
| A score is not scientific quality | Participation, entropy, review load, publication counts and numeric production are proxies. Model-generated rationales are hypotheses, not observations. | Separate chosen optimization target, independently observed effects and conceptual interpretation; use multiple objectives to expose Goodhart behavior, not protect an implicitly preferred institution. |
| New messages do not validate a new scientific institution | Types and schemas establish executable compatibility, not meaningful review/replication/funding behavior or social realism. | Validate protocol semantics against artifact histories and researcher responses; preserve degenerate and unexpected solutions as research outcomes. |
| Source generation still has a model/prompt/repair prior | Qwen3-8B and task framing constrain what is proposed. The optimizer may fail or exploit a trivial loss. No exhaustive creativity guarantee. | Version prompts/feedback and compare proposal mechanisms only after a substantive integrated slice works. Failures retain null loss, not fabricated successes. |
| Arbitrary source may be nondeterministic or malicious | Bounded no-network Docker contains this local prototype; source can still use system entropy/time. Replay confirms only tested executions. | Keep fail-closed isolation/evidence, richer deterministic runtime or remote hardened sandbox if public execution is needed. Do not execute source in host/browser. |
| Current source loop is a small engineering driver | Actual previous observations condition new source, and selected SystemSpecs are retained. It is not yet the persistent restart-safe campaign controller used by the original parameter study. | Add program-artifact proposals to the durable ask/tell controller with failed/invalid observation receipts and resumable model calls. |
| New code/graph results are not yet game interventions | Existing UI replays/inspects mechanisms; numeric lab viewer shows paths. It does not let players install arbitrary newly generated institutions and observe live consequences. | Unified generated-code/graph replay and intervention UI using the same pinned evaluator; a visible artifact must correspond to real execution, not decorative animation. |
| No empirical validation of real science-policy conclusions | All current results are synthetic simulator/engineering results. More seeds alone do not resolve this. | Assumption comparisons, semantic outcome audits, external empirical calibration where possible; state claim boundaries in the paper. |

## Immediate sequence, rather than scaling up

1. Make source generation -> executable probe -> actual state transition ->
   measured loss -> result-conditioned code revision work and record it.
2. Generate multiple cooperating implementations plus their new protocol and
   process graph, with causally effective downstream use—not ledger storage only.
3. Integrate that general mechanism boundary with the live researcher lifecycle.
4. On the gradient track, replace fixed rule/order banks, expose projection
   error, and retain black-box validation of final executable systems.
5. Connect the resulting objects to objective compilation and game interventions.

These are open work items, not claims that all have been completed. Numerical
calculus tests, valid JSON and a rendered UI cannot stand in for them.
