## What is now executable

`utopia/optimization/native_workflow_domain_v4.py` provides:

- `workflow_design_space(anchor)`: a whole-SystemSpec `code-and-graph` domain
  accepted by the existing `NativeAdaptiveDesignCampaign` loss-feedback loop.
  Arbitrary institutional source, additional nodes/protocols and wiring remain
  possible. There is no list of permitted institutional policies.
- `require_workflow_candidate`: retain the twelve original scientific/effect
  contracts and actual plan/paper origins, while allowing their schedules to
  change. Copies hidden inside process delegates are counted as well. The old
  fixed-calendar guard still rejects the new timing contrast.
- `edit_workflow`: apply explicit phase edits and exact old/new edge pairs.
  Missing edges, unknown IDs or a causal contradiction fail; the helper does
  not guess another producer, rescale phases, repair code or rewrite metadata.
- `verify_workflow_interval`: inspect actual owner-bound native events for one
  occurrence of each protected effect per completed year, at the candidate's
  actual scheduled phase/order. This supplements, not replaces, cold physical
  checkpoint/response/code audits.

This family retains native opening, costs, production, grants, publication and
ledger effects. Its one-annual-schedule rule, original catalog/project authority,
exact paper/plan origins and fixed initial state/image are explicit technical
domain limits, not claims about the general graph engine. It does not add an
outcome, participation, fairness, novelty or improvement veto to either loss.
Extra native production is outside this particular fixed-effect comparison;
the wider system API is not reduced to this family.

Zero-latency producers must execute before consumers; delayed memory is
explicit. Real native effects and resource/domain mutations precede ledger
closure. Pure institutional memory/context machinery can still execute after
that closure, as the original history office does. Descriptive
`metadata.native_process.order` is not an execution authority; the original
anchor already has a stale descriptive list, which is retained literally.

## One hand-designed timing control, not an invented improvement

`post_funding_cost_control` changes exactly three schedules and five edges of
R7. It keeps every node, source, numeric parameter, initial state and metadata
literal. The actual runner order, not the metadata list, determines execution.

| Block | Original | Timing control |
| --- | --- | --- |
| Liquidity code and transfer effects | phases78/79 | phases161/162, after funding |
| Annual native costs | phase80 | phase163, after transfer effects |
| Selection observation | costs.world | submission.world |
| Liquidity observation | submission.world | funding.world, actual post-grant state |
| Native selection trigger | costs.next | submission.next |
| Native cost trigger | submission.next | funding.next |
| Communication trigger | funding.next | costs.next |

Production, selection, publication, citation and native funding otherwise keep
their existing phases. The control explicitly requires free integer phases;
it never silently renumbers another candidate. Moving the observation edge is
part of the joint intervention: it is not a pure cost-timing causal estimand.
Its real-world outcomes and improvement are unknown; tests are not scientific
results. The native grant amount/slot rules are not edited, but a later real
trajectory may change eligibility or realized costs when activity changes.
