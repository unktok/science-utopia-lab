## Why the previous search does not answer the central question

The user's target is objective-conditioned optimization of executable scientific
systems, including newly authored rules, institutions, wiring and processes.
Universal world autograd, forced novelty, human policy adoption and improvements
in every scientific value are not prerequisites for that target.

The [closed corrected study](../results/native-corrected-choice-search-closed-v1.json)
contains24 own slots, but only8 are free-code/graph proposals;16 are numeric
comparators. Of the8 free proposals,6 repeat a measured parent's full scientist
input path and fail to improve the loss,1 changes that path adversely and1 is an
execution null. There are no new wire/schedule edits. Equal AST is not equivalent
to equal behavior, and different AST did not establish a useful intervention.

This is not evidence that institutional optimization is impossible. Measured
developer controls change native behavior and outcomes. It is also not evidence
that the35B designer intrinsically lacks the required ability: effective
exploration, author information, task interface and model capability have not
been isolated. The present strategy confuses nominal expressivity with exercised
search. Keeping the best supplied parent is legitimate minimization, not invention.

The terminal reference weakly dominates all23 complete own archive points on U-up,
K-down. Changing a nonnegative resource coefficient on that same archive cannot
create an own strict advantage. This is observed support, not a global bound.
Re-ranking or adding unused seeds alone does not fix failed proposal generation.

## Implemented prospective information intervention

`utopia/optimization/native_literal_change_feedback_v1.py` explicitly declares a
source-bound option in a NEW request's strategy provenance. For the bounded
production author profile, every planner/editor/submission prompt compares the
current draft with its exact selected parent. The pane separately shows:

- literal source change and standard-Python AST equality or unassessed status;
- non-code parameters and artifact/interface fields changed;
- added/removed nodes, wires, schedules, ordering and root changes;
- explicit row omissions and ambiguous/invalid drafts, never false zero change;
- distribution configuration, which is not itself implemented world behavior.

The pane persists after unrelated reads and reflects undo, rather than reporting
only the immediately preceding write. All values are data. Only a fixed
source-owned explanatory note enters SYSTEM. Old requests without the option
have no pane/note; historical source-bound journals stay in their original
checkouts. No generated code is executed on the host or rewritten. No node,
policy, code body, loss, merit score, novelty gate or finish veto is supplied.
This only addresses missing change evidence, not downstream semantic validity
or efficient search in the entire open program space.

Implementation is not an effectiveness result. SCRIPTED transport and historical
request regressions must be distinguished from real model/backend calibration,
new submitted proposals, actual native trajectories and measured loss advantages.
