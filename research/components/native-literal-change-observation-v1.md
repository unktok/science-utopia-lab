# Passive observations of literal institutional edits

This is analysis preparation, not an active designer mode or a new scientific
result. The [observer](../../utopia/optimization/native_literal_change_observation_v1.py)
compares literal full system documents: root fields, identified nodes,
non-code parameters, artifact interfaces, direct Python source, connections
and schedules. List ordering and multiplicity are retained separately from
membership. Missing, null, boolean, integer and floating values remain distinct.
Canonical JSON object-member order is **not** assessed. Unknown/ambiguous nodes,
unsupported runtimes and unavailable/invalid source are unassessed, not zero
changes and not disallowed designs. Output rows have an explicit finite limit.

Normalized Python AST equality excludes source locations, comments and spacing;
it is not universal program/world equivalence. Other artifact fields (ports,
state schema, label), parameters, nodes and root changes remain visible even
when the source AST matches. AST differences likewise establish neither actual
consumer behavior nor usefulness. Actual native receipts/inputs and loss must
establish those separate layers. No plan prose is interpreted or repaired, and
no change, novelty, gain or minimum AST difference is required to finish.

and [expanded projection](../results/native-literal-change-journal-replay-v1.json)

The32 component probes mentioned there were already recorded in those sessions;

A real adaptive/C/g1 topic-priority change is a positive control: its unchanged
source AST does **not** hide its changed `topic_priorities` parameter. This
protects against the misleading inference that equal source AST means an
unchanged institution. The first prototype incorrectly looked for an invented
`language` field. Actual-schema replay caught its unassessed result before any
author exposure; that failure is retained. The corrected observer uses the real
`CODE_SCHEMA` / `CODE_IMPLEMENTATION` constants and a statically validated
native artifact fixture. Twenty-five light tests pass at c75a6386; the
[JUnit](../data/literal-change-observation-v1/after-artifact-interface-fields.xml)
is software evidence, not25 scientific experiments.

## Re-executable closed-journal analysis

The [CLI reader](../../scripts/reports/native_author_literal_changes_v1.py)
validates original session bindings, every dispatch/completed-prefix chain,
terminal coverage, exact file hashes, and each available before/next full
document against its original receipt. It retains rejected edit attempts and
unavailable full views without inventing a result. It never reconstructs a
missing document by executing code or trusting plan prose. Closed sessions
are explicit inputs; an export of two sessions is not all eight proposals.
Caller-declared scientific source cleanliness is checked separately; this
reader is not the original source-bound whole-native cold replay.

At clean12997729 the observer/journal/CLI tests pass70 overlapping cases in
1.32seconds. The actual public CLI then runs twice on those two original native
sessions (handles25033/80490, both exit0), with byte-identical sealed outputs:
28 original completed steps, all8 edit attempts assessed from saved documents,
all8 changed source texts with equal AST and unchanged other configuration.
The exact54,510-byte [report](../data/native-author-literal-changes-v1/original-native-sessions.json)
and [JUnit](../data/native-author-literal-changes-v1/pytest.xml) are retained only
after both commands exit. The [receipt](../results/native-author-literal-changes-preparation-v1.json)
records sources, handles and exact file/content hashes. No diagnostic is thereby
exposed to an author; eight edits in two sessions are not eight independent
design histories or evidence of causal feedback benefit.

From a clean committed reader, use distinct fresh external outputs twice:

```text
.venv/bin/python -B -m scripts.reports.native_author_literal_changes_v1 \
  --origin-source ORIGINAL_SCIENTIFIC_SOURCE \
  --session ORIGINAL_CLOSED_AUTHOR_SESSION \
  --session ANOTHER_ORIGINAL_CLOSED_AUTHOR_SESSION \
  --output FRESH_EXTERNAL_REPORT_JSON
```

The current scientific source, requests, loss, budgets and selections are
unchanged. No production author imports the observer, and no prompt exposes
this new diagnostic. Whether such passive feedback would help a designer
implement its own proposal is an open prospective question, not an adopted
follow-up, a demonstrated cause of failure or a measured improvement. The
complete unchanged study's effects/costs still inform the next research choice.
