# Read-only native trajectory projection prototype

This is a fixed-field reader of completed original-world checkpoints, **not**
a new scientist world, designer, loss or already connected author feature.
Active25be72cd/plan33e32136 remains unchanged. It prepares the observation-axis
comparison in the [design note](../publication/native-open-observability-comparison-design-v1.md),
without dispatching that study or assuming its scientific value.

`utopia/optimization/native_trajectory_projection_v1.py` takes a decoded native
checkpoint plus explicit source/system/seed/horizon and the caller-bound actual
file SHA256. It requires a completed boundary, consecutive closed ledger years,
literal typed values, original event order and distinct tracked paper identities.
It reconciles each saved annual actor balance and category with original
transactions. Annual vectors are not copied backwards from final resources.

Every year includes original authors' opening/closing resources and activity,
all actual collected accounting categories/residuals, native phase witnesses
in their recorded order, fixed event-type counts, recorded project commands
and base native plan snapshots. New tracked content, accepted decision
occurrences and distinct accepted content are separate. Plan snapshots are
not newly created projects; tracked contents do not count all submission
attempts. Arbitrary prose, paper text, ratings and nonselected events are
omitted under a fixed field contract, never a favorable-outcome or size filter.

This component checks the supplied binding and accounting. It does not prove
the caller's file digest, full source/physical validity, causal mechanisms,
native behavior equivalence or allowed reference/unused-data access. A future
author assembler must enforce its own data bank and original cold proof.
Missing data raises rather than becoming a filled trace, loss or new merit veto.

## Reproduce a bounded read

`scripts/reports/native_trajectory_projection_v1.py` verifies the original file
and reader-source hashes before/after the read, exports to a fresh path outside
the explicitly declared scientific evidence root, and retains the sealed
projection plus its byte count. It starts no model or generated code and is
not a whole-study audit. Use the approved project interpreter:

```text
<approved-project-python> -m scripts.reports.native_trajectory_projection_v1 \
  --evidence-root <original-run-root> --checkpoint <completed-checkpoint> \
  --source-commit <scientific-source> --system-fingerprint <submitted-system> \
  --seed <literal-world-seed> --years <completed-horizon> --output <fresh-report.json>
```

For scientific use, join it to original physical/source evidence first. No
new model call, institution admission criterion, selection, scientific gain or
publication-readiness claim follows from a successful projection.
