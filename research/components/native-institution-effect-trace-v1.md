# Native execution and received information traces

The cold trace joins independently audited native checkpoints, literal code
inputs/results, declared process delegates, resource ledgers and completed
HTTP inputs. It explains what ran and what information appeared in a request;
it does not change a loss or identify a beneficial causal mechanism.

For each original founder and saved year boundary, it retains resources,
activity and reconciled ledger terms, plus conserving transfer legs. Boundaries
are not within-year minima or continuous participation time. Native code calls
are attributed using original physical records, including wrapped delegates;
ambiguous duplicate receipts stay ambiguous rather than being greedily assigned.
Missing pre-initial states and partial worlds remain distinct from completed
outcomes. The generated source itself is never executed by this reader.

Two different information checks are kept separately. The historical raw
envelope substring proof remains unchanged. The new check applies the original
source's institutional_context_prompt to actual stored prefixes, retaining
scientific payloads while using its declared prompt-local audit aliases. It
then matches that exact rendered text in recorded completed HTTP inputs. A
match does not identify a unique actor, independent call, beneficial
interpretation or causal effect; an unmatched prefix is not proof of absence.
