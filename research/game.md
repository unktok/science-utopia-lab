# ScienceUtopia Game 構想

## 目的

エージェント、研究テーマ、論文、査読、資源、制度の循環を、ログの羅列ではなく「世界が動いている」と感じられる体験へ変える。ゲームは研究 simulator の飾りではなく、観測、説明、介入、仮説形成のインターフェースである。

## 体験の核

- ピクセルアートの大学、研究所、会議、資金機関、政府機関
- 研究者エージェントが移動し、共同研究し、執筆し、評価を受ける
- 論文や仮説が知識マップへ現れ、流行、停滞、分岐、再発見が見える
- プレイヤーは制度設計者として、評価・公開・資金・情報流通のルールを変更する
- 介入の短期的な成功と長期的な副作用が時間を通じて現れる
- 同じ world を巻き戻し、別制度の counterfactual を比較する

## ゲームループ案

1. 世界と政策目標を選ぶ。
2. 限られた制度 primitive と予算から科学システムを構成する。
3. 一年または一フェーズを進め、イベントと主要指標を観察する。
4. 個々のエージェント、論文、decision の因果履歴を掘る。
5. 制度を維持・変更し、複数年の帰結を比較する。
6. シナリオ終了時に、単一スコアではなく trade-off と予期しない結果を振り返る。

## UI 原則

- **世界と証拠を接続する:** キャラクターや建物から、実際のevent log・decision・resource ledgerへ辿れる。
- **時間を制御できる:** pause、step、fast-forward、checkpoint、branch を提供する。
- **指標の出所を見せる:** 数字から構成イベントまで drill-down できる。
- **不確実性を隠さない:** seed 間分布、まだ確定していない評価、観測不能な真値を区別する。
- **研究モードとゲームモードを分離しすぎない:** 同じ simulation API と保存形式を使う。

## 技術境界

simulator は headless で決定的に再生可能な event stream を生成し、ゲームクライアントはそれを購読する。UI が科学ロジックを持たないようにする。

```text
Simulation core -> canonical events -> replay/state projection -> game UI
                                      -> analysis pipeline
                                      -> experiment audit
```

最初の vertical slice は、既存の1年 run を再生し、10人の研究者、5本の投稿、査読、採否、資金移動を見られる read-only viewer とする。その後、制度パラメータを一つ変更して branch run を開始できるようにする。

## 研究との接続

- 人間が選ぶ制度と optimizer が選ぶ制度を比較する。
- 制度説明の提示方法が理解と選択へ与える影響を調べる。
- 人間の介入系列を、探索 prior や preference data として利用する。
- ただし研究参加を行う段階では、同意、プライバシー、倫理審査の必要性を別途判断する。
