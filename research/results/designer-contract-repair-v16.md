# Designer interface repair and recurrence prevention V16

The original edit-language defect and accompanying software defects are fixed
prospectively. This is not evidence that a useful new scientific institution
has been invented. No new scientific-world evaluation or generated-source
execution is part of this verification.

## Repairs

1. Arbitrary edit operands explicitly enumerate all JSON types rather than
   relying on the backend's incorrect empty-schema conversion. Both designer
   transports choose JSON mode up front; strict host validation remains. No
   error-triggered fallback, missing-field repair or baseline substitution.
2. Tool-specific required/allowed fields come from one authoritative registry.
   Diagnostics select the tool branch, identify the bad field and canonicalize
   only the validation view for stable sorted-journal replay. Authored strings,
   edit values and operation-array order remain literal.
3. Bounded read memory retains resolved addresses and small observed values;
   omissions and old-document observations are explicit. Alternating and alias
   revisits of an unchanged observation generate notices, not action bans.
4. Exact serialized POST UTF-8, byte hash, host-schema hash and original HTTP
   text are recorded. Parsed/sorted dictionaries are not wire-byte evidence.
5. Production factories, campaign CLIs and search-enabled server startup require
   a real-backend interface certificate. Every author POST cold-replays it and
   rechecks live model/version metadata. Missing, partial, failed, expired or
   source/model/backend/image/protocol-mismatched evidence blocks dispatch.

Certificates expire after24h and fingerprint all `utopia/**/*.py`. They are
trusted local operator evidence, not binary/remote attestation. Recalibrate after
operator-known backend changes even if its reported version is unchanged.
Tests, contributor instructions, PR checklist and the
[operator guide](../../docs/designer-preflight.md) record this requirement.
There is no novelty, fairness, quality or scientific-merit promotion veto.

### Normal planning did not produce a usable institution

Both arms read actual selection source parameters and attempt categorical
distribution configuration rather than looping only on empty parameters.
However, they propose unverified participation-state fields, omit/misplace
factor logits, and their final finish is rejected by static compilation.
Neither original terminal has a candidate, scientific loss or native execution.

The new probe wrapper originally labels returned `generation_failure`
dictionaries `finished:true`. That wrapper bug is fixed and regressed; original
wrapper files remain untouched. The compact report explicitly records the
disagreement and uses original hashed generation terminals as status authority.
Also, strict replay at frozen a4 rejects an error receipt whose root-oneOf
message changes under sorted JSON key order. Do not call that a successful
cold planning audit. Final source fixes the diagnostic-order defect; tests
cover direct roundtrips and full rejected-action → valid-finish cold replay
without another model call. They do not upgrade old journals or prove new
ordinary planning succeeds under the final source.

## Remaining boundary

The technical interface can be tested independently and a broken or unverified
one cannot silently start the production workflow. A valid interface is not a
reliable autonomous designer. In particular, these two short normal planning
checks do not show useful invention, effective loss-guided redesign or measured
scientific improvement. The one-shot transport has scripted certificate tests
but no actual V16 certificate; its production gate stays closed until its own
explicit finite calibration. No larger native campaign is started here.
