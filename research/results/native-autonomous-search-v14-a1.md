## Exact observed failure

All nine complete parsed JSON drafts first attempt
`/mechanisms/17/parameters/code_artifact/source`. Index17 is within the actual
19-element array, but identifies `open-domain-actions`, implemented by
`native.domain.commands.v1`. Its parameters contain `actor_schemas`,
`artifact_schemas` and `capabilities`, with no `code_artifact`. The exact first
failure is therefore **a missing field on the wrong mechanism**, not an
out-of-range first array index. The actual selection Python node is
`world.selection` at index7.

The JSON audit records the original pointer token, container type and length
at each step using the pinned JSON edit primitive on a private JSON copy.
Every failed draft stops at its first edit. Later entries targeting indices19,
20 or21 are retained but explicitly marked not replayed; they are not counted
as separately observed edit failures. No candidate is manufactured by moving
those operations to another index or inserting missing fields.

The other three responses have raw HTTP output with `done_reason=length` and
4096 completion tokens. The adapter labels them `transport-error` because
generation raises before returning parsed output. Here that label denotes
truncated model output, not an inferred network outage. Their exact raw
assistant/HTTP content remains archived; no partial JSON or source is repaired.
