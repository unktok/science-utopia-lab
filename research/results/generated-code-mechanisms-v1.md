# Generated implementation-code mechanisms: initial execution proof, incomplete search

Date: 2026-10-31. This is an engineering result, not a science-policy result or
a successful optimized institution. [Compact evidence](generated-code-mechanisms-v1.json).

## What actually works

Local Qwen3-8B generated actual Python source, a state schema and a new
`paper_scores` artifact schema. The artifact was produced at clean source
`c539319b6a909a8c63b703cdc742cdfeb1385f29`, not selected from the numeric AST
operator catalog. Its imports, loops, dictionaries and branching executed
inside the pinned no-network Docker image
`sha256:c5cd0ef1703ee77e4a056f51695d2d73b17d9bf07b167763058c0802105f8833`.

The generic SystemSpec runner connected a deterministic two-period fixture,
the generated institution, the production PaperTracker and an artifact ledger.
Five real production-tracker state transitions were recorded: zero accept,
five reject. Five score artifacts were stored. Here “production” means the
actual repository domain class, **not** a live multi-agent researcher run.
All five fixture paper identities were preserved in the exercised publication
records. No fairness floor or acceptance quota was added.

The initial source required three model attempts: an undefined variable,
then non-JSON-serializable output, then a valid implementation. Actual errors
were returned to Qwen; the host did not repair the generated algorithm by hand.
These three model calls consumed 69.076 seconds of recorded model duration.

Independent frozen-source replay reproduced SystemSpec, summary, full events,
event hash and checkpoint exactly. Splitting after period one and resuming
reproduced the uninterrupted checkpoint and event stream. Publication counts
were independently recomputed from actual publication events. These checks
did not make new model calls. Source/model/image/context/result hashes and
the raw replay locator are retained in the compact evidence.

## What did not work

The next proposed code revision received the actual initial source and host
observation under `loss = -accepted_record_count`. Three attempts failed:

1. Manifest declared `publication_records`/`review_summary`, but the function
   still emitted `paper_scores`.
2. The repaired function emitted both old and new port names, still violating
   its own declared interface.
3. The next response had an invalid conditional expression (SyntaxError).

These calls consumed 121.467 seconds of recorded model duration. No loss was
fabricated for invalid source. No optimized system was selected. The second
objective arm was not reached in this final run. Therefore the two-objective
source-optimization experiment is **incomplete**, even though the initial
generated implementation executes and reproduces.

The full-optimization publisher intentionally refuses incomplete campaigns.
A separate `scripts/reports/code_mechanism_probe.py` publishes only this
initial-source execution proof and the failure receipts. The current default
is non-thinking JSON generation; an explicit experimental reasoning profile
omits the JSON token grammar and still validates final text. Its usefulness
has not been established by this result.

## Semantic limitations observed in the successful source

An executable source file is not automatically a meaningful novel institution.
This particular generated algorithm is still a simple score threshold (8,
above all fixture review scores), despite its “commons” label. Its state stores
the current decisions/artifacts but overwrites earlier entries and does not
use history to influence decisions. The artifact loop reuses the preceding
loop's `author_id`, so artifact actor associations can be wrong; its payload
schema alone does not detect that error. These are source-inspection findings,
not additional numerical outcome claims. The artifact ledger does not retain
all reference metadata for a full downstream semantic audit.

Thus the backend is no longer restricted to our arithmetic DSL, but the model
has not demonstrated creative, memory-dependent institution discovery. JSON
validation proves compatibility only. Semantic reference integrity, meaningful
institutional memory, generated consumers, researcher responses and full
ecosystem effects remain open. The generic code API supports arbitrary JSON
memory; the exercised model source did not make substantive use of it.

## Next non-scale work

Separate protocol design, implementation synthesis and executable repair rather
than asking a small model to keep every field synchronized in one response.
Retain freedom to invent schemas/algorithms, but bind implementation to its
sealed protocol. Then generate a producer and consumer together and demonstrate
causal downstream use, not just artifact storage. Use explicit artifact-reference
checks rather than treating a label or model rationale as evidence.

The remaining world, process, differentiation, original-backend and game gaps
are tracked in the [non-scale inventory](../audits/non-scale-limitations-v1.md).
No seed/population increase is needed to investigate these next questions.
